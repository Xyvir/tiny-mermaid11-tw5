## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Diagram author → %%{init}%% | Author-supplied widget attributes / fields / in-source directives are untrusted; they cross into Mermaid render config |
| Plugin-injected %%{init}%% → Mermaid render | Plugin prepends a directive built only from whitelisted non-secure keys |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-06-06 | Tampering | %%{init}%% injection key set | mitigate | Only NON_SECURE_INJECT_KEYS (theme, look, fontFamily, fontSize, themeVariables, darkMode) are injected; junk widget attributes (class/style/text) and secure keys are excluded (V5 Input Validation, O-01). Test 'does not inject class/style' asserts this. |
| T-06-07 | Elevation of Privilege | author sets securityLevel via %%{init}%% to enable XSS | mitigate | securityLevel is excluded from NON_SECURE_INJECT_KEYS so the plugin never injects it; and Mermaid's own secure array blocks author-supplied securityLevel escalation at the library level (D-03). No plugin change needed beyond the exclusion. |
| T-06-08 | Tampering | injection ordering (prepend vs append) | mitigate | Prepend (D-02) ensures the author's literal %%{init}%% comes last and wins via Mermaid's last-wins merge — the plugin cannot silently override an author's explicit choice. Verified live in Task 3 (Assumption A3). |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs (RESEARCH.md Package Legitimacy Audit: Not applicable — all deps vendored). |
