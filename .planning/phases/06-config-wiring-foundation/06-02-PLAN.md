<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Site owner → config tiddler → initialize() | Trusted site-owner JSON flows into Mermaid global config via buildSiteConfig() |
| getOptions() output → config | getOptions() captures arbitrary widget attributes / fields (untrusted-shaped keys like class/style) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Tampering | buildSiteConfig() key copy loop | mitigate | CONFIG_WHITELIST gates every key from the config tiddler before it reaches initialize() (V5 Input Validation, O-01). Non-whitelisted keys (class/style/DOM junk) are dropped silently. |
| T-06-04 | Elevation of Privilege | startOnLoad override via config tiddler | mitigate | buildSiteConfig() `continue`s past startOnLoad so the hardcoded false always wins (D-07). Test 'startOnLoad: false' asserts this. |
| T-06-05 | Elevation of Privilege | securityLevel escalation | accept (by design) | securityLevel IS settable from the SITE config tiddler (site owner is trusted, V4 Access Control); default 'loose' is an intentional tradeoff enabling click navigation (documented). Diagram-author securityLevel escalation is blocked downstream (Plan 03 / Mermaid secure array). |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs (RESEARCH.md Package Legitimacy Audit: Not applicable — all deps vendored). |
</threat_model>
